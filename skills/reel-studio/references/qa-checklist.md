# Before showing a render

Run `check <project>` (loudness, peak, duration, voice inside scene windows, contact sheet), then go through this list with the stills and the preview.

## Content

- [ ] Every UI on screen is a real capture; nothing redrawn or generated; demo data and demo features are labelled.
- [ ] No invented numbers, customers, reviews, awards.
- [ ] The voice says what is on screen, in the same order; each on-screen word appears when spoken.
- [ ] One CTA, the same keyword on screen and in the voice.
- [ ] Copy follows the brand address (вы/ты) and Russian typography.

## Readability (look at 375 px width)

- [ ] Headlines and captions readable; UI text that carries the message ≥ 22 px in the 1080 frame.
- [ ] Nothing important in the top 220 px, bottom 360 px, right 150 px.
- [ ] Overlapping fragments keep ≥ 60 % of the back one visible.
- [ ] No app background visible between separately cut UI pieces.
- [ ] No text crosses the busiest part of the background.

## Motion

- [ ] Every transition has a reason; strong effects ≤ 3.
- [ ] Recordings: the camera leans in before each click and returns; the cursor never jumps; clicks land on visible elements.
- [ ] No dead frames: something meaningful happens at least every 1–2 s.
- [ ] First and last frames work as thumbnails.

## Sound

- [ ] −14 LUFS ±1, true peak ≤ −1 dBTP.
- [ ] Music audibly under the voice, effects on clicks and reveals, nothing masks words.
- [ ] Listen for mispronounced names and merged words; fix the text, not the audio.

## Delivery

- [ ] 1080×1920, 30 fps, H.264 + AAC, BT.709 limited range.
- [ ] Tell the user what you did not check (e.g. you cannot listen to audio; on-device playback).
